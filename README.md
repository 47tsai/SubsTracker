# SubsTracker — 訂閱管理與提醒系統

基於 **Cloudflare Workers + KV** 的輕量級訂閱到期提醒。在網頁中管理訂閱，到期時透過 Telegram / Bark / 企業微信 / ntfy 等 **11 種管道** 推送，並內建通知紀錄與排程紀錄，方便除錯。

**適合**：個人自行架設、網域、會員資格或帳單的到期提醒。  
**不適用情境**：多人協作或複雜的企業簽核流程。

## 🚀 快速開始

```text
部署 Worker
  → 使用 admin / password 登入（請立即修改密碼）
  → 系統設定：選時區（台灣使用者通常可選 Asia/Taipei（台北時間））
  → 系統設定：允許傳送的時段（例如只想在早上 8 點傳送，就填入 08）
  → 至少啟用一種通知管道並填妥 Token，點選「測試」，直到測試成功
  → 在「訂閱清單」新增訂閱（可用預設提醒規則：到期前 7／3／1 天及到期當天）
  → 到期後請到「通知紀錄」查看是否已傳送，以及跳過原因
```

若中途卡住，先看下方 [常見問題 FAQ](#-常見問題-faq)。

## 📦 部署

### 方式一：命令列（推薦）

```bash
git clone https://github.com/wangwangit/SubsTracker.git
cd SubsTracker
npm install

# Linux / macOS
export CLOUDFLARE_API_TOKEN=你的token
# Windows PowerShell
# $env:CLOUDFLARE_API_TOKEN="你的token"

npm run deploy:safe
```

`deploy:safe` 會：

1. `npm run setup` — 自動建立 / 綁定 KV（`SUBSCRIPTIONS_KV`）
2. `npm run deploy` — 部署 Worker

部署成功後，終端會顯示類似：

`https://subscription-manager.<你的子域>.workers.dev`

### 方式二：GitHub Actions

1. Fork 本儲存庫  
2. 儲存庫 **Settings → Secrets and variables → Actions** 增加：

| Secret | 說明 |
|--------|------|
| `CLOUDFLARE_API_TOKEN` | 需 Workers 編輯 + KV 編輯權限 |
| `CLOUDFLARE_ACCOUNT_ID` | 可選 |

3. 推送到 `master` / `main` 或手動執行 **Deploy** workflow  

### 預設登入

| 項 | 值 |
|----|-----|
| 使用者名稱 | `admin` |
| 密碼 | `password` |

**登入後請立刻在「系統設定」修改密碼。** 若將預設密碼暴露於公開網路，帳號可能遭到接管。

### 忘記密碼

Cloudflare Dashboard → **Workers & Pages → KV** → 開啟 `SUBSCRIPTIONS_KV` → 編輯 key `config` 的 JSON，修改 `ADMIN_PASSWORD` 後儲存。

## ✅ 第一次必做設定

開啟 **系統設定**，建議依序做完：

### 1. 修改密碼

管理員使用者名稱 / 密碼改成自己的。頁面若提示仍是預設 `admin`，請務必處理。

### 2. 時區

- 台灣使用者通常可選：**`Asia/Taipei`（台北時間）**；其他地區請選擇實際使用的時區。
- 所有「距離到期還有幾天」「幾點傳送通知」都以這裡為準

### 3. 允許傳送的時段

| 填入的值 | 意思 |
|----------|------|
| `08` | **僅**中國標準時間 **8 點那一小時**會傳送（約 8:00–8:59 的那次整點檢查） |
| `08, 20` | 早上 8 點、晚上 8 點各可能傳送一次 |
| **留空** 或 `*` | 每個整點都會執行檢查，是否傳送則依提醒規則與時段設定而定 |

要點：

- 系統每小時整點執行一次檢查（Cron：`0 * * * *`，按 UTC 觸發，但判斷用你設定的時區）。
- 若填入 `08`，但目前是 19 點：**不會傳送**。通知紀錄中出現「不在允許傳送的時段」屬於 **正常跳過**，並非故障。
- 設定頁下方有即時預覽（會顯示「目前會傳送／不會傳送」）。**修改後請點選儲存**，預覽才與伺服器端一致。

### 4. 至少啟用一種通知管道

啟用通知管道 → 填入 Token／Chat ID 等資訊 → 點選 **測試通知**，確認手機或群組中能收到。

常用通知管道：

| 管道 | 你需要準備 |
|------|------------|
| Telegram | Bot Token + Chat ID；Forum 群可選 Topic ID |
| Bark | Device Key；自建可填 Server |
| 企業微信 | 群機器人 Webhook |
| ntfy | Server（預設 ntfy.sh）+ Topic；可選 Token |
| WPUSH | API Key；可選 Channel / Topic 編碼 |
| 電子郵件 | Resend API Key + 收發郵箱 |
| Webhook | 任意 HTTP 地址 + 可選模板 |

### 5. 加一條測試訂閱

- 將到期日設得近一些，提醒規則可使用 **「套用預設 7/3/1/當天」**
- 或臨時新增一條「到期前 0 天 / 到期當天」，並把「允許傳送的時段」改成目前時段進行測試（測完改回）

## 📋 日常怎麼用

### 訂閱清單

| 操作 | 說明 |
|------|------|
| 新增 / 編輯 | 名稱、週期、金額、分類、農曆等 |
| **複製** | 複製一筆（名稱帶「副本」），適合 esim 保號等同構訂閱 |
| 續訂 | 手動延長週期並記錄付款 |
| 停用 / 啟用 | 停用後不再提醒（在清單中重新整理即可，不必重新載入整個頁面） |
| 測試 | 立即對該訂閱傳送測試通知 |
| 歷史 | 付款紀錄 |
| 篩選 | 關鍵字、循環/重置模式、**狀態**（正常/即將到期/已過期／已停用）、分類 |

### 提醒規則（每條訂閱可多條）

預設提醒規則：**到期前 7 天、3 天、1 天 + 到期當天**。

**重要語義（很多人誤解這裡）：**

> 「到期前 N 天」= **只在剩餘天數正好等於 N 的當天傳送一次**  
> **不會**從第 N 天起每天連發。

若要 7、6、5… 都提醒，需要多條規則，或使用預設 7/3/1/當天。

其他類型：

- **到期當天**
- **到期後**：每隔 X 小時提醒，直到你續費（受「允許傳送的時段」限制）

### 訂閱模式：循環 vs 到期重置

| 模式 | 一句話 | 例子 |
|------|--------|------|
| **循環訂閱** | 未過期就從**目前到期日**往後接 | 會員 6/15 到期，6/3 續費 → 新的到期日約 7/15 |
| **到期重置** | 從**付款日**重新算一整段週期 | 保號卡儲值日重新起算 180 天 |

### 週期快速選項

表單中可用 **季度 / 半年 / 一年** 快速選項（實際上是 3 個月 / 6 個月 / 1 年）。  
國曆可勾選 **「每月最後一天」**（適合「每月月末提醒」；農曆下不用這個）。

### 備份與遷移

在 **系統設定** 最下方：

1. **匯出備份** → 下載 JSON（預設可不包含金鑰）
2. 換帳號變更或重新安裝後 **匯入**  
   - **合併**：按訂閱 ID 覆蓋同名，保留其他  
   - **覆蓋**：先清空再整包匯入（有風險，先匯出目前資料）

升級大版本或遷移 CF 帳號前，**先匯出一份**。

## 🔔 通知的運作方式（重點必讀）

```text
每小時整點 Cron
  → 看現在是否在「允許傳送的時段」（按時區）
  → 看每條啟用中的訂閱是否命中某條提醒規則（精確日/小時）
  → 去重（同一天同一規則不會重複傳送）
  → 發到你啟用的管道
  → 寫入「通知紀錄」+「排程日誌」
```

「允許傳送的時段」是傳送窗口。例如填 `08, 12`，命中同一條以日期為單位的規則後通常只在 08 點傳送一次，12 點不會重複傳送；它不是每天傳送兩次的計畫。

| 現象 | 常見原因 |
|------|----------|
| 任務歷史：不在允許傳送的時段 | 目前時間不在你設定的 `08` 等時段內 → **正常** |
| 在窗口內但 sentCount=0 | 今天沒有規則被命中（還沒到「正好 N 天」） |
| 有 failed 紀錄 | 管道設定錯誤／Token 失效 / 網路拒絕 → 看錯誤詳情 |
| 一天只在 8 點附近收到 | 你只設定了 `08`，符合預期 |
| 希望一天提醒多次 | 把允許小時寫成多個，如 `08, 12, 20`，或留空 |

**清單上的「提醒」列**：顯示該訂閱真實多規則摘要（如 `提前 7/3/1 天 · 到期當天`），與後台 `reminder_rules` 一致。

## ❓ 常見問題 FAQ

### 1. 為什麼沒有收到通知？

依序檢查：

1. **系統設定**是否啟用了管道？「測試」能否收到？  
2. **允許傳送的時段**是否包含「現在」？（填了 `08` 則只有 8 點）  
3. **時區**是否是 `Asia/Shanghai`？  
4. 該訂閱是否 **啟用**？提醒規則是否啟用？  
5. 今天是否正好命中「到期前 N 天／到期當天」？  
6. 開啟 **通知紀錄**：  
   - 若狀態為 failed，請查看管道回報的錯誤訊息  
   - 只有跳過、寫著「不在允許傳送的時段」 → 等到設定的小時  
   - 完全沒有相關紀錄 → 可能還沒到整點檢查，或規則未命中  

### 2. 任務歷史寫「不在允許傳送的時段 / 不在設定時段」？

說明定時任務跑了，但目前時段不允許傳送。  
例如只允許 `08`，晚上 19 點跳過 → **正常**。  
到你設定的時區上午 8 點再查看是否傳送。

### 3. 設定了「到期前 7 天」，為什麼第 6～1 天沒有通知？

這是依精確日期觸發的設計：只在剩餘 **正好 7 天** 那天發。  
若要在多個日期提醒，請新增多條規則，或用預設 **7/3/1/當天**。

### 4. 清單提醒一直顯示「提前 7 天」？

目前版本清單會讀真實規則摘要。請 **強制重新整理**（Ctrl+Shift+R）。  
若仍不對，開啟瀏覽器開發者工具 → Network → `subscriptions`，看返回中是否有 `reminderRulesSummary`。

### 5. 複製按鈕看不見或沒有顏色？

操作列有 **複製**（青色）。強制重新整理，按鈕位於「編輯」後面。  
若只有灰字，確認已部署含主題樣式的最新版本。

### 6. 循環訂閱和到期重置有什麼區別？

請參考上方表格：會員續費用 **循環**；依儲值日重新計算週期則用 **重置**。

### 7. 如何備份 / 換 Cloudflare 帳號？

系統設定 → **匯出備份** → 新環境部署後 **匯入**。  
覆蓋模式會清空現有訂閱，操作前請先匯出目前資料。

### 8. Telegram 如何傳送到群組話題（Topic）？

系統設定 → Telegram → 填寫可選 **Topic ID**（對應 `message_thread_id`）。  
一般私訊／一般群組可留空。

### 9. ntfy 怎麼配？

啟用 ntfy → Server 預設 `https://ntfy.sh` → 填入自己的 Topic → 手機 ntfy App 訂閱同一 Topic → 點測試。

### 10. WPUSH 怎麼配？

啟用 WPUSH → 在 [設定頁](https://wpush.cn/settings) 取得 API Key → 可選擇填寫管道／Topic 編碼 → 點測試。成功條件為介面返回 `code === 0`。

### 11. 主控台中的 `beacon.min.js` / cloudflareinsights 報錯？

那是 **Cloudflare 統計指令碼**，不是本專案的業務程式碼。一般可忽略，與訂閱清單無關。

### 12. Authentication error [code: 10000]（部署時）

Token 權限不足或 Wrangler 快取問題：檢查 API Token 權限，必要時刪除 `.wrangler/` 後重試。

### 13. 第三方系統想調通知介面？

在系統設定中產生 **第三方 API 令牌** 後：

```bash
curl -X POST "https://你的網域名稱.workers.dev/api/notify/你的令牌" \
  -H "Content-Type: application/json" \
  -d '{"title":"標題","content":"內文"}'
```

也可使用要求標頭：`Authorization: Bearer 你的令牌`。

## 🔐 安全提醒

1. **立刻修改** 預設 `admin` / `password`  
2. 不要將 API Token、Bot Token 等機密資訊提交至 Git  
3. 備份 JSON 若勾選「包含敏感設定」，請當密碼一樣保管  
4. 請勿在對話或截圖中長期顯示 Cloudflare API Token；若已外洩，請前往 Dashboard **輪替 Token**
